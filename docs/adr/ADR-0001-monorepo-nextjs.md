# ADR-0001: Монорепозиторий Turborepo + Next.js

| Поле | Значение |
|---|---|
| Статус | Accepted (зафиксировано ретроспективно) |
| Дата | 2026-07-21 |
| Авторы | HouseMaster Team |

## Контекст

HouseMaster развивается как платформа с несколькими будущими приложениями и сервисами (web-клиент, воркеры AI-конвейера, общие пакеты типов и утилит). На старте нужно было выбрать организацию кодовой базы и основной фреймворк.

Решение было принято де-факто в начале проекта; данный ADR фиксирует его формально, чтобы серия ADR имела полную историю.

## Решение

1. Кодовая база организована как **монорепозиторий** на **Turborepo + pnpm workspaces**:
   - `apps/*` — приложения (сейчас: `apps/web`);
   - `packages/*` — общие пакеты (типы, конфигурации, утилиты).
2. Основной фреймворк приложения — **Next.js (App Router) + TypeScript + Tailwind**.
3. Корневые скрипты (`dev`, `build`, `lint`) делегируются в Turborepo (`turbo run ...`).

## Обоснование

- Единый репозиторий упрощает согласованные изменения между фронтендом, API-слоем и общими пакетами — критично на ранней стадии, когда доменная модель ещё меняется.
- Next.js покрывает и UI, и API-слой (Route Handlers), что позволяет MVP жить в одном деплой-юните (один контейнер в Cloud Run).
- Turborepo даёт кэширование сборок и параллельный запуск задач; при появлении новых сервисов (например, AI-воркеров) они добавляются как `apps/*` без реструктуризации.
- TypeScript сквозь весь стек — единая система типов от БД до UI.

## Последствия

- CI/CD и Dockerfile должны учитывать монорепозиторий (сборка через `turbo prune` для минимального контекста).
- Инфраструктурный код (Terraform) вынесен в отдельный репозиторий и **не** входит в этот монорепо; в монорепо живёт только каталог `infrastructure/` с CI-конфигурацией приложения (см. ADR-0002).
- Новые сервисы обязаны следовать структуре `apps/*` / `packages/*`.
