---

## Mission

HouseMaster — цифровая операционная платформа для управления жилым фондом Республики Казахстан. Система автоматизирует эксплуатацию МКД, соединяет ОСИ, жителей и государственные сервисы в единой AI-assisted среде.

## Vision

Стать стандартной инфраструктурой ЖКХ для каждого дома Казахстана: от подачи заявки жителем до предиктивного обслуживания инженерных систем на базе AI.

## Architectural Principles

### 1. GCP First, KZ Where Required

Google Cloud Platform — основная инфраструктура для всех служебных данных, AI, вычислений и инструментов разработки. Исключение строго одно: персональные данные граждан РК размещаются на серверах в Казахстане в соответствии с Законом №94-V. Это не компромисс с GCP-стратегией — это её точное ограничение.

### 2. AI Native

AI — не надстройка, а операционное ядро платформы. Каждый рабочий процесс проектируется с вопросом «что здесь делает модель?». Vertex AI, Gemini, Vector Search — первоклассные компоненты, а не интеграции. AI-конвейер работает исключительно с обезличенными данными.

### 3. Privacy by Design, Not by Compliance

Персональные данные жителей не попадают в GCP-контур — архитектурно, а не политикой. Граница ПДн — это физическая граница контуров, а не фильтр в коде. Если данные классифицированы как ПДн, единственный способ их передать в GCP — необратимая агрегация или анонимизация.

### 4. Data Sovereignty

Данные граждан РК хранятся на серверах в Казахстане. Архитектура разработана так, что смена KZ-провайдера или переход в будущий GCP-регион РК не требует изменения прикладной логики — только конфигурации. KZ-контур использует стандартный PostgreSQL без vendor-специфичных расширений.

### 5. PostgreSQL Everywhere

Единая СУБД-парадигма для всех контуров: Cloud SQL (PostgreSQL) в GCP, стандартный PostgreSQL в KZ. Единый ORM (Prisma), единые паттерны миграций, единая модель транзакций. Никакого Firestore, никакого NoSQL для операционных данных. BigQuery — только для аналитики.

### 6. No Personal Data in AI Pipeline

Vertex AI, Vector Search и Gemini получают только данные об объектах инфраструктуры. Правило абсолютное: ФИО, контакты, история обращений конкретного жителя в AI-конвейер не передаются. AI работает с классом дефекта, серией дома, типом оборудования — не с личностью.

### 7. Infrastructure as Code, No Manual Exceptions

Всё в Terraform, без исключений. Ресурс, созданный вручную, должен быть импортирован в Terraform-state до следующего sprint review. Manual exceptions — технический долг первого класса.

### 8. Zero Trust Between Contours

Контуры GCP и KZ не доверяют друг другу по умолчанию. Каждый cross-contour вызов аутентифицирован, авторизован и залогирован. Передаются только UUID-ссылки и агрегированные данные. Прямых FK между контурами нет.

### 9. Event-Driven Integration at Boundaries

Синхронные вызовы между контурами запрещены на критических путях. Интеграция между GCP и KZ, между HouseMaster и внешними системами (операторы связи, eGov, коммунальные платформы) — через события и очереди. Pub/Sub — стандартный транспорт внутри GCP-контура.

### 10. Cloud Neutral Only at the KZ Boundary

Cloud-neutral абстракция применяется точечно: только для KZ-контура, только для слоя доступа к данным. GCP-контур использует нативные сервисы без абстракции. Это осознанный trade-off: vendor lock-in в GCP принят явно (ADR-0002), vendor neutrality в KZ — требование безопасности.

## Engineering Principles

### 11. Sequential Phase-Gating

Следующая фаза не начинается до тех пор, пока предыдущая не верифицирована в рабочей среде. Документация не опережает работающий код более чем на один sprint. Принцип «написал — запустил — проверил» применяется к каждой задаче.

### 12. Explicit Over Implicit

Архитектурные решения фиксируются в ADR, границы данных — в Data Classification Matrix, контракты между контурами — в Boundary Contract. Неявные допущения — источник ошибок при смене контекста или команды. Если решение не зафиксировано — оно не принято.
