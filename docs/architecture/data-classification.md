# HouseMaster — Data Classification Matrix

| Поле | Значение |

| Документ | docs/architecture/data-classification.md |

Этот документ является единственным источником истины по классификации данных. Любое решение о хранении, передаче или обработке данных верифицируется по этой матрице.

---

## Категории данных

| Категория | Определение | Контур хранения |
|---|---|---|
| **PII** — Personal Data | Данные, прямо или косвенно идентифицирующие физлицо | KZ только |
| **Operational** — Служебные | Данные об объектах инфраструктуры, не содержащие ПДн | GCP Cloud SQL |
| **Knowledge** — База знаний | Нормативы, документы, технические справочники | GCP Cloud Storage + Vector Search |
| **AI Data** — AI-обработка | Обезличенные данные для AI-конвейера | GCP Vertex AI |
| **Technical** — Техническая инфраструктура | Логи, метрики, конфигурации, секреты | GCP (обезличенно) |
| **Analytics** — Аналитика | Агрегированные данные по фонду | GCP BigQuery |

## Матрица классификации

### PII — Персональные данные (KZ-контур)

| Сущность | Поля | Владелец | Хранение | В AI | Чувствительность |
|---|---|---|---|---|---|
| `User.email` | Идентификатор входа | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `User.fullName` | ФИО | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `User.phone` | Контактный телефон | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `User.passwordHash` | Хэш пароля | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `Session` / `RefreshToken` | Данные аутентификации | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `Apartment.apartmentNumber` + `userId` | Адрес проживания (связанный) | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🔴 HIGH |
| `ResidentRequest.text` (будущее) | Текст обращения жителя | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🟡 MEDIUM |
| `AuditLog` (действия физлиц) | История действий | Физлицо | KZ PostgreSQL | ❌ Запрещено | 🟡 MEDIUM |

| `Asset` | type, location, serialNumber, status | Организация | GCP Cloud SQL | ✅ Разрешено | 🟢 LOW |

### Knowledge — База знаний (GCP)

| Сущность | Поля | Владелец | Хранение | В AI | Чувствительность |
|---|---|---|---|---|---|
| СНиП / ГОСТ / нормативы | Полный текст документов | Публичные | GCP Cloud Storage + Vector Search | ✅ Основа RAG | 🟢 LOW |
| Типовые дефекты | Описание, классификация, методы ремонта | HouseMaster | GCP Cloud Storage | ✅ Разрешено | 🟢 LOW |
| Паспорта зданий | Технические характеристики | Организация | GCP Cloud Storage | ✅ Разрешено | 🟢 LOW |
| Серии домов | Конструктивные особенности | Публичные | GCP Cloud Storage | ✅ Разрешено | 🟢 LOW |
| Проектная документация | Схемы, чертежи | Организация | GCP Cloud Storage | ✅ Разрешено | 🟡 MEDIUM |

### AI Data — Данные для AI-конвейера (GCP Vertex AI)

| Данные | Источник | Трансформация | Чувствительность |
|---|---|---|---|
| Описания дефектов (обезличенные) | Inspection.notes | Без привязки к userId | 🟢 LOW |
| Характеристики активов | Asset (полностью) | Прямое использование | 🟢 LOW |
| Технические параметры зданий | House + Asset | Прямое использование | 🟢 LOW |
| Векторные эмбеддинги нормативов | Нормативная база | OCR + chunking | 🟢 LOW |
| Статистика дефектов по серии | WorkOrder + Inspection | Агрегация по типу, не физлицу | 🟢 LOW |

**Абсолютно запрещено передавать в AI:**
- Любые поля из KZ-контура
- userId в необезличенном виде
- Текст обращений жителей
- Данные аутентификации

### Technical — Техническая инфраструктура

| Данные | Хранение | В AI | Чувствительность |
|---|---|---|---|
| Секреты (OAuth, DB passwords) | GCP Secret Manager | ❌ Запрещено | 🔴 HIGH |
| Логи приложения | GCP Cloud Logging | ❌ (метаданные без ПДн) | 🟡 MEDIUM |
| Метрики Cloud Run | GCP Cloud Monitoring | ❌ | 🟢 LOW |
| Terraform state | GCP Cloud Storage (tfstate bucket) | ❌ | 🟡 MEDIUM |
| Docker образы | GCP Artifact Registry | ❌ | 🟢 LOW |

### Analytics — Аналитика (GCP BigQuery)

| Данные | Источник | Условие | Чувствительность |
|---|---|---|---|
| Статистика дефектов по домам | WorkOrder + Inspection | Агрегация, без userId | 🟢 LOW |
| KPI ОСИ | Organization + WorkOrder | Агрегация по организации | 🟢 LOW |
| Тренды по типам активов | Asset + Inspection | Технические данные | 🟢 LOW |
| Количество заявок (без текста) | ResidentRequest.count | Счётчики, без ПДн | 🟢 LOW |

## Правила передачи данных между контурами

| Разрешено | Запрещено |
|---|---|
| UUID пользователя (pseudonym) из KZ → GCP | ФИО, email, phone из KZ → GCP |
| Агрегированные счётчики без привязки к личности | Сырые данные обращений жителей → GCP |
| Технические ID объектов из GCP → KZ | Прямые SQL-запросы из одного контура в другой |
| Статусы WorkOrder для отображения в PWA | JWT-токены жителей → GCP |

## Правило классификации для новых сущностей

При добавлении новой сущности обязательно ответить на четыре вопроса:

1. **Субъект данных** — физлицо (→ KZ) или юрлицо/объект (→ GCP)?
2. **Идентифицируемость** — можно ли по этим данным установить личность? (да → KZ)
3. **AI-допустимость** — содержит ли поле ПДн? (да → запрет на передачу в AI)
4. **Регуляторная классификация** — подпадает ли под Закон №94-V?

Если хотя бы один ответ указывает на ПДн → данные идут в KZ-контур без исключений.
