# HouseMaster — Boundary Contract

| Поле | Значение |
|---|---|
| Документ | docs/architecture/boundary-contract.md |
| Статус | Proposed (при принятии ADR-0005) |
| Дата | 2026-07-25 |
| Связано | ADR-0005, data-classification.md, Architecture-Principles.md |

Этот документ определяет архитектурный контракт между GCP-контуром и KZ-контуром. Нарушение контракта — архитектурная ошибка, не технический debt.

---

## 1. Как контуры взаимодействуют

Контуры взаимодействуют **только через API приложения**. Прямых сетевых соединений между базами данных нет: ни federated queries, ни database links, ни репликации между Cloud SQL и KZ PostgreSQL.

```
GCP-контур                         KZ-контур
   │                                   │
   │  Next.js API (Cloud Run)          │
   │  ├── prismaGcp.*  ──────────────► Cloud SQL
   │  └── prismaKz.*  ──────────────► KZ PostgreSQL
   │
   └── Один процесс, два клиента.
       Приложение — единственная точка пересечения.
```

Порядок вызовов при cross-contour операции:
1. Запрос авторизуется (JWT верифицируется против `prismaKz`)
2. Бизнес-логика определяет нужные контуры
3. Запросы выполняются последовательно или параллельно в зависимости от зависимостей
4. Результат объединяется в приложении и возвращается клиенту

## 2. Идентификаторы между контурами

Единственный разрешённый идентификатор для cross-contour ссылок — **UUID v4**.

| Идентификатор | Использование | Хранение |
|---|---|---|
| `userId` (UUID) | Ссылка из GCP-сущностей на физлицо | Хранится в GCP как `createdById`, `assignedToId` — без ПДн |
| `organizationId` (UUID) | Связь пользователя с организацией | UUID в обоих контурах, но полные данные организации только в GCP |
| `houseId`, `assetId`, `workOrderId` | Ссылки из PWA на объекты GCP | UUID передаётся в KZ-контур только в ответах API |

**UUID — pseudonym, не идентификатор личности.** По UUID из GCP-контура невозможно установить личность без обращения к KZ-контуру. Это pseudonymization по GDPR и аналог в контексте Закона РК №94-V.

## 3. Данные, разрешённые к передаче через границу

### GCP → KZ (в ответах API для PWA)

| Данные | Форма | Условие |
|---|---|---|
| `workOrderId`, `status`, `priority` | Примитивы | Только для запросов авторизованного пользователя |
| `houseAddress`, `apartmentNumber` | Строки | Только адрес дома пользователя |
| AI-результаты: статус осмотра, рекомендации | Текст | Обезличенные |
| Счётчики и статистика | Числа | Без привязки к конкретному физлицу |

### KZ → GCP (в запросах от авторизованного пользователя)

| Данные | Форма | Условие |
|---|---|---|
| `userId` (UUID) | Идентификатор | В JWT как `sub`, используется как ссылка |
| `organizationId` (UUID) | Идентификатор | Для фильтрации данных организации |
| Запрос на WorkOrder | Структурированный объект | Текст заявки, тип проблемы — без ПДн о третьих лицах |

## 4. Данные, запрещённые к передаче

### Абсолютные запреты (не зависят от контекста)

| Данные | Направление | Причина |
|---|---|---|
| `email`, `fullName`, `phone` | KZ → GCP | ПДн физлица в GCP-контур |
| `passwordHash`, токены аутентификации | KZ → GCP | Данные аутентификации |
| История действий физлица (raw) | KZ → GCP | ПДн |
| Текст обращений жителей | KZ → Vertex AI | ПДн в AI-конвейер |
| Любые ПДн | → Vertex AI / Vector Search | Принцип #6 Architecture Principles |
| Сырые данные из KZ-БД | → BigQuery | Аналитика без ПДн |

### Условные запреты (разрешены только при выполнении условий)

| Данные | Условие для разрешения |
|---|---|
| Адрес проживания | Только в ответе конкретному пользователю, не в логах |
| UUID пользователя | Только в пределах авторизованной сессии |
| Статистика по дому | Только в агрегированном виде (≥5 записей в выборке) |

## 5. Где проходит граница персональных данных

Граница ПДн — физическая граница KZ-контура. Формально:

```
Всё, что записывается в KZ PostgreSQL — ПДн или данные аутентификации.
Всё, что записывается в Cloud SQL — служебные данные без ПДн.
```

Исключений нет. Если данные нужны в обоих местах — они хранятся только в KZ-контуре, в GCP — только UUID-ссылка.

**Граница в коде** — это выбор `prismaClient`:
- `prismaKz.*` — любая операция с ПДн
- `prismaGcp.*` — любая операция со служебными данными

Код review policy: PR с `prismaKz.*` запросами, содержащими поля `email`, `fullName`, `phone` в `select` — автоматически блокируется, если данные передаются дальше чем в ответ на HTTP-запрос инициатора.

## 6. Обработка ошибок на границе

| Сценарий | Поведение |
|---|---|
| KZ-контур недоступен | GCP-функции продолжают работу; PWA показывает состояние деградации; аутентификация недоступна |
| GCP-контур недоступен | KZ-аутентификация продолжает работу; служебные данные недоступны; PWA показывает кэшированные данные |
| Таймаут cross-contour запроса | Операция отменяется; не производится частичной записи в один контур без другого |
| Orphaned UUID | Плановая сверка (reconciliation job); soft delete с retention |
