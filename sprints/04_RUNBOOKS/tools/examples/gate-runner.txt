pipes that stdout as stdin into `validate --template commit`. The forbidden-list
placeholder is never auto-filled by gate-runner — this run correctly comes back
FAIL on no_next_gate (exit 1), same as filling the template by hand always has
throughout this session. Final exit code is validate's (1 here).

Command (composite — draft-commit-gate, missing required flags):
node gate-runner.mjs draft-commit-gate --what "x"

Behavior: fill refuses immediately (missing --target/--commit-message); validate
is never run. Exit code is fill's refusal code (2), not validate's.

(exit code 2)

Command (composite mode, explicit --template guard):
node gate-runner.mjs draft-commit-gate --template COMMIT_GATE --what "x"

Behavior: refused before fill even runs — --template is implied by the mode and
must not be passed explicitly (guards against it silently overriding the mode's
own --template value, since both would otherwise land in the same argv).

Refused: --template is implied by this mode (COMMIT_GATE) — do not pass it explicitly.

(exit code 2)

the closure-record template yet in v0.1).

(exit code 2)
